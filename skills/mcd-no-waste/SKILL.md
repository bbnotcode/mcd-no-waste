# 麦麦不白花

把卡包变成一份可执行的用餐决策：先识别即将失效的权益，再结合真实需求判断，不把用券价格说成节省金额。

## 获取证据

使用用户已连接的麦当劳官方 MCP（https://mcp.mcd.cn）。工具前缀可能不同，按工具描述识别 `query-my-coupons`、`query-my-account` 等实际工具；下划线别名也可。没有连接时说明缺失，不能用演示数据冒充账户查询。

1. 查询 `query-my-coupons` 与 `query-my-account`。卡包按页读取，pageSize=200，最多5页；记录 totalPages、totalCount。超出上限、某页失败或重复页时说明结果不完整，不能声称全部查询完成。
2. 以 Asia/Shanghai 的当前时间判断。优先读取 tradeEndDateTime，其次 tradeEndDate；仅有日期时只能判断到期日，不能断言23:59仍可核销。不要用 enable=1 推导“此刻能在任意店使用”。
3. 如用户愿意考虑积分兑换，再查 `mall-points-products`，检查 status=2、上下架时间、所需积分及额外现金。进一步查看 `mall-product-detail` 确认 SKU、库存和兑换条件。积分接口只有本月/下月的到期汇总，不能编造具体到期日，也不能把已过期积分混入即将到期积分。

## 排序与决策

可将响应整理为 `{"coupons": {...完整卡包响应...}, "account": {...完整积分响应...}}`，通过标准输入运行随附 `scripts/analyze.py --now <带时区的ISO时间>`，得到不含券码、账户ID和签名图片链接的摘要。不必为使用脚本把私人响应保存到公开仓库。

先展示今天、未来3天、以后到期、时间待确认及已到期项。保留早餐等时段、到店/外送、星期、App或渠道限制。时间字段不足或矛盾时保留原文并标为待确认，不猜测。

再结合用户是否本来就打算吃、预算、餐品偏好和到店/外送需求给出“优先考虑 / 可以等等 / 不必特意消费”的建议。缺少用餐计划时先给到期清单，然后只问一个最关键的问题。不要根据标题自行算满减、叠券或节省金额；discountValue 可能是用券价，并非优惠差额。

用户选定具体用餐计划后，用真实地点确定门店，再调用 `query-store-coupons` 核验门店和订单类型；需要金额时使用餐品详情和 `calculate-price`。卡包券不能承诺可用于订单。仅支持App等无法在MCP核价的券，明确提示官方渠道确认。

## 输出

用中文简短给出：查询时间和覆盖范围、最紧急的权益及准确截止信息、积分本月/下月到期数量、建议和仍待核验的条件。没有到期风险就明确说无需赶着消费。工具失败与空卡包分开说明。

本 Skill 只做查询和建议。领取优惠券、兑换积分、抽奖、创建订单、添加地址或取消订单均须用户明确要求并确认具体操作。不要因为“帮我看看别浪费”执行这些操作。默认不创建后台提醒或定时任务。
